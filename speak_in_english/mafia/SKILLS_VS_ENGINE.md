# Навыки vizavi-motion и make-2d-video против движка Speak in English

Проверка перед тестовой сценой «NO FIGHTING!». Кода анимации ещё нет: никаких новых модулей и изменений в движке.

## 1. Что умеет каждый навык

### vizavi-motion (v1.6.1)
Это **методика**, а не код: 11 текстовых файлов, ни одной библиотеки, рига или рендерера.
- Режиссура до сборки: для каждой сцены 3–5 вариантов решения, выбор сильнейшего, подробная раскадровка (композиция, действие, камера, звук, вход и выход).
- Короткая проба главного риска до дорогой сборки.
- Обязательная итерация: первая сборка считается черновиком. Просмотр, исправления, проверка готового декодированного MP4 (кадры, длительность, звук, синхронность).
- Звук: SFX привязаны к контактам и действиям, акценты совпадают с монтажом.
- Честные статусы: «реализовано / видно в кадрах / проверено в движении / прослушано».
- По умолчанию **постоянно движущаяся камера и 60 fps** — это противоречит правилам канала (`hard_cut`, 30 fps). Правила владелицы важнее.

### make-2d-video (плагин 2d-video, v0.1.1)
Это **отдельная студия со своим стилем**: рисованные кодом «кинематографичные человечки-палочки» в профиль, контровой свет, 2.5D-декорации, Three.js, рендер через headless Chromium (Playwright).
- `rig2d.js` (281 строка): ~28 готовых поз (point, shrug, crossArms, facepalm, holdFront, sit, fall...), плавный переход между позами `posesAt`, «дыхание» `breathe`, **цикл ходьбы и бега `walkPose`** с IK ног (стопы стоят на полу), лица `EXPR` (≈20 выражений: cry со слезами, nervous с потом, scared, shocked...), гигантские лица `bigFace`.
- `fx2d.js`: линии скорости, «кольца» реакции, пыль, дождь, свет, мебель-заготовки.
- `player.js`: переходы между планами — whip, zoom, flash, dip.
- `audio/sfx.py`: процедурная библиотека ~30 звуков (footstep, whoosh, swish, hit, impact, pop, ding, tick, clock, phonering, murmur, roomtone...), `mix.py` — сведение до −14 LUFS.
- Конвейер под **закадровый голос**: транскрипция, `shots.json`, по движению камеры в каждом плане.

## 2. Что подходит для нашей сцены

| Задача | Чем делать | Почему |
|---|---|---|
| **Персонажи и стиль** | наш `hq.js` (`human()`) | Утверждённый иллюстрированный стиль канала. Фигурки-палочки из make-2d-video — другой мультфильм, смешивать нельзя. |
| **Ходьба** | своя ходьба для `human()`, **по математике `walkPose`** | Готовый цикл рассчитан на профильную фигурку (единицы ~240, лицо вбок). Наш риг фронтальный, поэтому берём принцип (фаза, стопа на полу, IK колена, покачивание корпуса, отмашка рук) и переносим его на ноги `hq.js`. |
| **Жесты** | наш `pose.reach()` + **схема `posesAt`/`blendPose`** | Позы make-2d-video заданы точками другого скелета, напрямую не подходят. Но сама идея «ключи поз по времени + плавный переход» (≈15 строк) переносится как есть. Список поз (point, shrug, crossArms, facepalm, holdFront) — готовое ТЗ для нашей библиотеки жестов. |
| **Мимика** | наш риг (12 настроений) + новые выражения | `EXPR` нарисован точками-глазами в другом стиле, его отрисовка не подходит. Берём список как чек-лист (cry, nervous/пот, scared). |
| **Предметы в руках** | наш `items.L/R` (уже есть `teacup`, `coffee`, `phone`...) | В make-2d-video предметы проще нашего. |
| **Падающая чашка, осколки** | своё (≈40 строк) | Ни в одном навыке нет физики предметов. |
| **Несколько персонажей** | наш движок | Мизансцены, слои и `hard_cut` уже отработаны в `trial.js`, `pizzas.js`. |
| **Быстрый наезд, whip** | наша камера + **формулы переходов из `player.js`** | Переходы whip/zoom там по 1–2 строки, переносятся в наш рендер. |
| **Линии скорости, «кольца» реакции** | **`fx2d.js` (speedLines, rings)** | Простые эффекты, переносятся почти дословно (≈10 строк). |
| **Звуки для теста** | `audio_v2.py` (drop, clank, gasp, squeak, rimshot, tick) + **`sfx.py` из 2d-video** (footstep, swish, hit, whoosh) | Новые звуки писать не нужно. ElevenLabs не используется. |
| **Процесс** | **vizavi-motion** | Варианты гэгов → проба риска → черновик → просмотр → исправления → проверка готового MP4. Без её «камеры всегда в движении» и 60 fps. |

## 3. Что всё равно придётся сделать самим

1. **Ходьба для фронтального рига** — перенос `walkPose` на ноги `hq.js`: стопа «прилипает» к полу, колено по IK, ботинки смотрят по ходу движения. Нужен маленький совместимый крючок в `hq.js` (без него ногами нельзя управлять снаружи); старые эпизоды он не меняет, это проверяется побайтным сравнением кадров.
2. **Ладонь с вытянутым пальцем** для «показывает пальцем» (в нашем риге есть только ладонь и кулак) — рисуется поверх кисти через существующий `items`.
3. **Новые выражения**: жуткая улыбка Tony, подмигивание, крошечные зрачки от ужаса. Нужен крючок в `hq.js` для рта и глаз, отрисовка — в отдельном файле.
4. **Физика предметов**: падение чашки с вращением, удар, осколки, брызги чая.
5. **Действия с предметами**: кастет уходит в карман, бита задвигается ногой под стол (тем же управлением ногой, что и ходьба).
6. **Сама сцена**: декорация зала, 5 персонажей (Alex, Tony, Bruno, Marco, Mrs. Patterson), раскадровка, временные пузыри EN + RU.

Объём модулей стал **меньше** первоначальной оценки: формулы ходьбы, смешивания поз, переходов, эффектов и звуки берутся готовыми.

## 4. Нужно ли менять план производства

Существенно — нет. Основой остаётся наш движок: только он даёт утверждённый стиль персонажей, 16:9, `hard_cut`, пузыри с переводом и весь конвейер озвучки. Уточнения:
- Этап «ядро анимации» стал короче: ходьба, позы и переходы портируются из make-2d-video, а не пишутся с нуля.
- Звук для черновиков и теста — из готовых библиотек (`audio_v2.py` + `sfx.py`), без новых генераторов.
- В производство добавляется процесс vizavi-motion: короткая проба риска → черновик → просмотр → исправления → проверка готового MP4.
- Переходить на make-2d-video как на движок **не рекомендую**: другой стиль (палочки в профиль), закадровый голос вместо диалогов, камера всегда в движении, тяжелее рендер (Chromium).
